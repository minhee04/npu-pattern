# Mini NPU Simulator

## 1. 프로젝트 소개

MAC(Multiply-Accumulate) 연산을 이용하여 2차원 패턴을 분류하는 Python 콘솔 프로그램이다.

Cross 필터와 X 필터의 MAC 점수를 비교하여 입력 패턴을 분류한다.

## 2. 실행 환경

- Python 3.8 이상
- json, time 표준 라이브러리 사용
- 외부 라이브러리 미사용

## 3. 파일 구성

- `main.py`: MAC 연산 및 패턴 분류 프로그램
- `data.json`: 크기별 필터와 테스트 패턴 데이터
- `README.md`: 프로젝트 설명 및 결과 리포트
- `screenshots/`: 프로그램 실행 및 프로젝트 증빙 캡처

## 4. 실행 방법

프로젝트 폴더에서 다음 명령어를 실행한다.

```bash
python main.py
```

실행 후 메뉴에서 원하는 기능을 선택한다.

1. 사용자 입력 모드 (3x3 고정)
2. JSON 테스트 모드 (5x5, 13x13, 25x25)
3. 성능 측정
0. 종료

사용자 입력 모드에서는 각 행에 공백으로 구분된 숫자 3개를 입력한다.

입력 예시:

```text
1 0 1
0 1 0
1 0 1
```

행 또는 열의 개수가 맞지 않거나 숫자가 아닌 값을 입력하면 다시 입력하도록 안내한다.

## 5. 주요 구현 내용

### MAC 연산

중첩 반복문으로 두 행렬의 같은 위치에 있는 원소를 곱하고 합산한다.

### 행렬 검증

행과 열의 개수 및 숫자 입력 여부를 검사한다.

JSON 데이터에서는 필터와 입력 패턴의 행렬 크기가 예상 크기와 일치하는지 확인한다.

### 라벨 정규화

예상 정답 라벨은 `+`, `Cross`, `cross`를 `Cross`로 통일하고, `x`, `X`는 `X`로 통일한다.

필터 키도 대소문자와 표기 차이를 정규화한다.

- `CROSS`, `Cross`, `cross`, `+` → Cross 필터
- `X`, `x` → X 필터

이를 통해 데이터의 표기 방식이 달라도 동일한 분류 기준을 적용할 수 있다.

### 패턴 분류

두 MAC 점수를 비교하여 더 높은 점수를 가진 필터를 선택한다.

두 점수의 차이가 epsilon(1e-9)보다 작으면 동점으로 판단한다.

모드별 동점 출력 규칙은 다음과 같다.

- 사용자 입력 모드: `판정 불가`
- JSON 테스트 모드: `UNDECIDED`

JSON 테스트에서 `UNDECIDED`가 반환되면 예상 정답과 일치하는 분류 결과가 아니므로 FAIL로 집계한다.

### JSON 처리

패턴 ID에서 행렬 크기를 추출하고 해당 크기의 필터를 선택한다.

입력 행렬의 크기를 검증한 뒤 예상 정답과 실제 결과를 비교한다.

필터 데이터 누락, 필터 키 누락, 행렬 크기 오류 등은 해당 테스트 케이스의 FAIL로 처리하며 프로그램 전체가 중단되지 않도록 예외를 처리한다.

### 성능 측정

각 행렬 크기별 MAC 연산을 100회 반복하고 평균 실행 시간을 측정한다.

측정 시간은 MAC 함수 호출 전후의 시간 차이를 기준으로 계산한다.

행렬 생성, 사용자 입력, 파일 읽기 및 콘솔 출력은 측정 구간에서 제외한다.

## 6. 결과 리포트

### JSON 테스트 결과

전체 테스트 6개 중 PASS 3개, FAIL 3개가 발생했다.

- PASS: `size_5_2`, `size_13_1`, `size_25_2`
- FAIL: `size_5_1`, `size_13_2`, `size_25_1`

실패 사례는 실제 분류 결과와 예상 정답이 일치하지 않았다.

각 실패 사례의 MAC 점수와 차이는 다음과 같다.

| 테스트 ID | Cross 점수 | X 점수 | 점수 차이 | 판정 |
|---|---:|---:|---:|---|
| size_5_1 | 0.9 | 0.8999999999999999 | 약 1.11e-16 | UNDECIDED |
| size_13_2 | 7.499999999999997 | 7.5 | 약 3.11e-15 | UNDECIDED |
| size_25_1 | 4.9 | 4.899999999999999 | 약 8.88e-16 | UNDECIDED |

세 사례 모두 두 MAC 점수의 차이가 epsilon(1e-9)보다 작아 UNDECIDED로 분류되었다.

부동소수점 연산에서는 표현 방식에 따라 매우 작은 오차가 발생할 수 있다. 따라서 epsilon 비교 정책을 적용하여 미세한 점수 차이를 동점으로 처리했다.

라벨 정규화를 통해 `+`와 `Cross`, `x`와 `X`의 표현 차이를 통일했다.

JSON 데이터의 필터 키와 행렬 크기 불일치도 별도로 검증하도록 구현했다.

제공된 데이터와 판정 정책을 유지했으며 임의로 정답이나 epsilon 값을 변경하지 않았다.

### 성능 측정 결과

| 행렬 크기 | 평균 시간(ms) | 연산량(N²) |
|---|---:|---:|
| 3x3 | 0.000343 | 9 |
| 5x5 | 0.001322 | 25 |
| 13x13 | 0.003897 | 169 |
| 25x25 | 0.012013 | 625 |

행렬 크기가 N x N일 때 각 원소를 한 번씩 계산하므로 연산량은 N²이다.

따라서 MAC 연산의 시간 복잡도는 O(N²)이다.

실행 시간은 컴퓨터 환경과 시스템 상태에 따라 달라질 수 있다.

1. 저장소를 내려받는다.

## 8. 추가 기술 분석

### 8-1. MAC 연산 수식과 유사도

MAC 연산은 두 행렬의 같은 위치에 있는 원소를 곱한 뒤 모든 결과를 누적하여 하나의 점수를 계산한다.

수식은 다음과 같다.

\[
Score = \sum_{i=0}^{N-1}\sum_{j=0}^{N-1} Filter[i][j] \times Input[i][j]
\]

MAC 점수는 필터와 입력 패턴의 같은 위치에 있는 원소들의 곱을 모두 더한 값이다.

따라서 두 필터 중 더 높은 MAC 점수를 얻은 필터를 입력 패턴과 더 높은 연관성을 가진 분류 결과로 선택한다.

이때 MAC 점수는 현재 프로그램에서 사용하는 분류 기준이며, 일반적인 모든 패턴에 대해 절대적인 유사도를 보장하는 값은 아니다.

### 8-2. 라벨 정규화와 확장성

`normalize_label()`과 `normalize_filter_keys()`를 별도 함수로 분리하여 입력 데이터의 표기 차이를 통일한다.

이러한 구조는 라벨 처리 로직을 한곳에서 관리할 수 있어 유지보수가 쉽고 새로운 라벨을 추가하기에도 편리하다.

새로운 라벨을 추가할 경우 다음 절차를 따른다.

1. `normalize_label()`에 새로운 라벨 규칙 추가
2. `normalize_filter_keys()`에 필터 키 규칙 추가
3. `classify()`에 새로운 분류 기준 반영
4. 출력 결과와 JSON 테스트 데이터 추가
5. 정상 입력 및 예외 입력 테스트

### 8-3. 성능 측정 범위와 epsilon 정책

성능 측정은 MAC 함수 호출 전후의 시간만 측정한다.

행렬 생성, 사용자 입력, 파일 읽기 및 콘솔 출력은 측정 구간에서 제외한다.

동점 판정에는 epsilon = 1e-9를 사용한다.

이 값은 부동소수점 연산에서 발생할 수 있는 미세한 오차를 고려하기 위한 허용 오차이다. 점수 비교에서 불필요한 미세한 차이로 분류 결과가 달라지는 것을 방지하며, 데이터의 정밀도와 요구사항에 따라 조정할 수 있다.

JSON 테스트에서 UNDECIDED가 반환되면 예상 정답과 일치하는 분류 결과가 아니므로 FAIL 처리한다.

### 8-4. 대규모 행렬 처리와 최적화

MAC 연산의 시간 복잡도는 O(N²)이다.

예를 들어 25x25 행렬은 625번의 곱셈과 누적 연산을 수행하지만, 1000x1000 행렬은 1,000,000번의 연산이 필요하다.

행렬이 커질수록 연산 시간과 메모리 사용량이 증가한다.

입력 행렬과 필터 행렬은 각각 O(N²)의 공간을 사용한다. 현재 MAC 함수는 별도의 N x N 행렬을 생성하지 않으며 누적 점수만 저장하므로 추가 공간 복잡도는 O(1)이다.

대규모 행렬에서는 다음과 같은 최적화 방법을 고려할 수 있다.

- 블록 단위 연산을 통한 데이터 접근 효율 개선
- 메모리 접근 최적화
- 불필요한 데이터 복사 최소화
- 병렬 연산을 통한 처리 시간 단축

### 8-5. CPU와 NPU의 연산 특성 및 병목

CPU는 다양한 작업을 처리하는 범용 프로세서로, 복잡한 제어 흐름과 순차적인 연산에 강점이 있다.

NPU는 인공지능 연산에 특화된 프로세서로, 다수의 MAC 연산을 병렬로 처리하는 데 유리하다.

CPU에서는 반복문을 통한 순차적인 MAC 연산이 대규모 데이터에서 처리 병목이 될 수 있다.

NPU에서는 여러 MAC 연산을 병렬로 수행할 수 있지만, 데이터를 연산 장치로 전달하는 과정과 메모리 대역폭이 성능 병목이 될 수 있다.

따라서 대규모 연산에서는 단순한 연산 속도뿐 아니라 데이터 이동과 메모리 접근 구조도 중요하다.

## 9. 최종 정리

본 프로젝트에서는 Python의 중첩 반복문을 이용하여 MAC 연산을 구현하고, 서로 다른 크기의 입력 패턴을 두 필터와 비교하여 분류하는 프로그램을 개발했다.

사용자 입력, JSON 테스트, 성능 측정 기능을 구현했으며 행렬 검증, 라벨 정규화, 부동소수점 오차를 고려한 동점 판정 정책을 적용했다.

또한 테스트 결과 분석과 시간·공간 복잡도, 대규모 행렬 처리 및 CPU와 NPU의 연산 특성을 정리했다.
